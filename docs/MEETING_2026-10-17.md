## Decisions for the call

1. Use a small, versioned dataset-0.3 train/validation pilot for the next shared
   runs. Keep the one-clip dataset-0.1 diagnostic only for controlled debugging.
2. Keep the existing tiny-training gate, and require held-out action response
   before spending on main comparisons. CVAE's training pass does not waive this.
3. Keep the core at 64px: CVAE, matched numeric/spatial diffusion, controls and
   four synchronized futures. Gate 128px, auxiliary losses and extra model
   families on measured motion quality and remaining compute.
4. Assign report assembly and final packaging within the team. Technical owners
   supply their actual methods, results and contributions; these two assembly
   roles are still open.

Shrijeet's next diffusion experiment changes only the prediction representation:
RGB versus changes from frame 0, with identical architecture, data, loss, seed and
budget. It is a diagnostic proposal until generated samples pass the same tracker
and action checks. No SOTA, uncertainty or grade claim follows from implementing it.

## Demo to build toward

Click an object, drag a force arrow and compare four generated futures with the
simulator. Reversing the force or clicking a different object should visibly
change the correct object's motion. Keep the seed fixed across those interventions.
Show the prior-sampled CVAE and diffusion side by side, with honest live/cached
labels and local backup playback. This becomes convincing when those changes are
learned and measurable; interface polish cannot substitute for them.
